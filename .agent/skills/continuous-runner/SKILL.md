# Continuous Runner

## Purpose

Biến agent từ **reactive** (chờ user gọi) thành **proactive** (tự chạy liên tục). Quản lý task queue, theo dõi new work, auto-resume pipelines bị gián đoạn, và chạy improvement loop.

**Nguyên tắc**: Agent luôn có việc làm — nếu không có task mới thì cải thiện bản thân.

---

## Architecture

```
┌─────────────────────────────────────────────┐
│              CONTINUOUS RUNNER               │
│                                             │
│  ┌─────────────┐  ┌──────────────────────┐  │
│  │ Task Queue   │  │ Resume Queue         │  │
│  │ (new work)   │  │ (interrupted work)   │  │
│  └──────┬──────┘  └──────────┬───────────┘  │
│         │                    │              │
│         └────────┬───────────┘              │
│                  ↓                          │
│  ┌───────────────────────────────────────┐  │
│  │           SCHEDULER                    │  │
│  │                                       │  │
│  │  Priority: Resume > New > Improvement │  │
│  │                                       │  │
│  │  1. Check resume queue → auto-resume  │  │
│  │  2. Check task queue → execute next   │  │
│  │  3. If idle → run improvement loop    │  │
│  │  4. If still idle → consolidate memory│  │
│  └───────────────────────────────────────┘  │
│                                             │
│  ┌───────────────────────────────────────┐  │
│  │           WATCHDOG                     │  │
│  │                                       │  │
│  │  - Monitor running pipeline health    │  │
│  │  - Detect stuck phases (timeout)      │  │
│  │  - Auto-restart if recoverable        │  │
│  │  - Escalate if not recoverable        │  │
│  └───────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

## Task Queue

### Location: `.agent/task_queue/`

```
.agent/task_queue/
├── pending/
│   ├── 001-rentivo-e2e.yaml
│   ├── 002-rentivo-zalo-feature.yaml
│   └── 003-rentivo-payment.yaml
├── running/
│   └── (active task moved here)
├── completed/
│   └── (finished tasks archived here)
├── failed/
│   └── (failed tasks with error reports)
└── queue_config.yaml
```

### Task File Format

```yaml
# .agent/task_queue/pending/001-rentivo-e2e.yaml
id: "001"
created_at: "2026-07-02T10:00:00Z"
priority: 1  # 1=highest, 5=lowest
type: "e2e"  # e2e | feature_add | patch | improvement
project: "rentivo"
description: "App quản lý nhà trọ cho chủ trọ và người thuê"
command: '/wf_e2e "App quản lý nhà trọ" --project rentivo'
status: "pending"  # pending | running | completed | failed | paused
dependencies: []  # task IDs that must complete first
max_budget_tokens: 1400000
max_duration_hours: 8
auto_approve: true  # agent can auto-run without user confirmation
tags: ["greenfield", "property-management"]
```

### Queue Config

```yaml
# .agent/task_queue/queue_config.yaml
max_concurrent: 1  # tasks running simultaneously
max_retries: 2
idle_action: "self_improvement"  # what to do when queue is empty
auto_resume: true  # auto-resume interrupted tasks
priority_order:
  - "resume"       # interrupted tasks first
  - "patch"        # quick fixes
  - "feature_add"  # features for existing projects
  - "e2e"          # new projects
  - "improvement"  # self-improvement tasks
timeout_hours: 12  # max time per task before force-stop
```

## Scheduler Logic

```python
# Pseudocode for the continuous loop
while True:
    # 1. Check for interrupted tasks
    resumed = check_resume_queue()
    if resumed:
        execute(resumed)
        continue

    # 2. Check for new tasks
    task = get_highest_priority_pending()
    if task:
        if task.auto_approve or get_user_approval(task):
            move_to_running(task)
            execute(task)
            on_complete(task)  # → save memory + retro
            continue

    # 3. If idle → self-improvement
    if has_pending_improvements():
        run_improvement_cycle()
        continue

    # 4. If still idle → consolidate memory
    if needs_consolidation():
        consolidate_memory()
        continue

    # 5. Truly idle → wait for new work
    wait_for_new_task()
```

## Auto-Resume Protocol

When agent session starts:

```markdown
## Startup Protocol

1. Read `.agent/task_queue/running/` — any interrupted task?
   → YES: Read checkpoint → resume from last gate
   → NO: Continue to step 2

2. Read `.agent/task_queue/pending/` — any pending tasks?
   → YES: Sort by priority → execute highest
   → NO: Continue to step 3

3. Check improvement queue
   → YES: Run self-improvement cycle
   → NO: Report idle status
```

### Interrupted Task Recovery

```yaml
# Recovery decision matrix
last_phase_status:
  "gate_pass":
    # Was between phases — safe to resume next phase
    action: "resume_next_phase"
  "gate_revise":
    # Was in revision — resume revision
    action: "resume_revision"
  "mid_phase":
    # Crashed during phase — re-run current phase
    action: "rerun_current_phase"
  "gate_fail":
    # Failed — need human input
    action: "wait_for_human"
```

## Watchdog

Monitor running pipeline for health:

### Timeout Detection

```yaml
phase_timeouts:
  research: 30  # minutes
  brd: 60
  tech_design: 45
  ui_design: 45
  openspec: 30
  code_gen: 90
  testing: 45
  deployment: 30
```

If phase exceeds timeout:
1. Check if making progress (new files created?)
2. If stalled → force gate evaluation
3. If gate passes → move on
4. If gate fails → pause + notify

### Health Checks

Every 5 minutes during execution:
- Is agent still producing output?
- Are tokens being consumed?
- Are files being created/modified?
- Is cost within budget?

## Proactive Work Discovery

When idle, agent can discover work:

### 1. Scan for TODOs

```bash
grep -r "TODO" project_docs/ --include="*.md" | head -20
```

Convert high-priority TODOs → pending tasks.

### 2. Check Open Questions

```bash
cat .agent/memory/context/*/known_issues.md
```

Convert open issues → investigation tasks.

### 3. Check Improvement Queue

```bash
cat .agent/memory/skills/skill_effectiveness.md
```

Create improvement tasks for underperforming skills.

## Session Lifecycle

```
Agent Session Start
       ↓
  LOAD memory
       ↓
  CHECK resume queue → auto-resume?
       ↓
  CHECK pending queue → execute?
       ↓
  CHECK improvements → apply?
       ↓
  Execute task with full pipeline
       ↓
  Run self-improvement-loop
       ↓
  SAVE memory
       ↓
  CHECK next task → loop or idle
       ↓
Agent Session End (or continue)
```

## Guardrails

- **DO** always check resume queue first — don't abandon work
- **DO** respect priority order
- **DO** run self-improvement during idle time
- **DO** save checkpoint before session end
- **DO NOT** run more than `max_concurrent` tasks
- **DO NOT** exceed `timeout_hours` per task
- **DO NOT** auto-approve tasks with `auto_approve: false`
- **DO NOT** skip improvement loop — it's what makes the agent better

## Limitations
- The runner depends on Antigravity IDE session — it cannot run as a true background daemon.
- Task queue is file-based — no real-time notifications for new tasks.
- Session continuity depends on checkpoint files — if deleted, progress is lost.
