## 4. Cache-Specific Error Handling (current)

### In AbstractTwoTierCache
```kotlin
// Current pattern — try/catch around Redis operations
fun get(key: K): V? {
    // L1 check first
    val l1Value = caffeineCache.getIfPresent(key)
    if (l1Value != null) return l1Value
    
    // L2 check — wrapped in try/catch
    return try {
        val l2Value = redisTemplate.opsForValue().get(redisKey)
        // ...deserialize...
    } catch (e: Exception) {
        log.warn("L2 cache read failed for key={}: {}", key, e.message)
        null  // Graceful degradation — fall through to DB
    }
}
```

### Error Handling Pattern
- **L1 failure**: Should never happen (in-memory) — log ERROR + continue
- **L2 failure**: Expected (Redis down) — log WARN + fall through to DB
- **Serialization failure**: Log ERROR + evict stale entry + return null

## 5. NEW Error Patterns (to be added)

### Encryption Errors
| Scenario | Handling |
|----------|----------|
| Decrypt fail (wrong key) | Log WARN + evict entry + return null (graceful) |
| Encrypt fail (missing key) | Skip encryption + log WARN + store plaintext |
| Key provider failure | Bean creation fails → application won't start (fail-fast) |

### Compression Errors
| Scenario | Handling |
|----------|----------|
| Zstd native lib not found | `@ConditionalOnClass` → bean not created → no compression |
| Decompress fail (corrupted) | Log WARN + evict entry + return null |
| Threshold below minimum | Validation at startup → log WARN + default to 1024 |
