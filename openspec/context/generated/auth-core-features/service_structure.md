## Naming Conventions

| Type | Pattern | Example |
|------|---------|---------|
| Controller | `<Domain>Controller` | `AuthController`, `PolicyController` |
| Service | `<Domain>Service` / `<Feature>Service` | `AuthService`, `RbacEngine`, `PolicyEvaluator` |
| Entity | `<Name>Entity` | `UserEntity`, `RefreshTokenEntity` |
| Repository | `<Name>Repository` | `UserRepository`, `DomainRepository` |
| Request DTO | `<Action>Request` or `<Action>RequestDto` | `LoginRequest`, `RegisterRequestDto` |
| Response DTO | `<Name>Response` | `AuthResponse`, `DomainResponse` |
| Exception | `<Name>Exception` | `InvalidCredentialsException`, `AccountLockedException` |
| Config | `<Feature>Config` / `<Feature>Properties` | `SecurityConfig`, `SecurityProperties` |

## Architectural Pattern

- **Hexagonal Architecture**: `adapter/in/web`, `adapter/out/persistence`, `application`
- **DI**: Constructor injection via Kotlin primary constructor (no `@Autowired` fields)
- **DTO Placement**: Mixed — some in controller files (inline), some in service files
- **Repository Pattern**: Spring Data JPA `JpaRepository` interfaces
