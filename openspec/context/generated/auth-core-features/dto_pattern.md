## DTO Patterns Observed

1. **Controller-layer DTOs** — validation annotations (`@NotBlank`, `@Email`, `@Size`) on controller DTOs
2. **Service-layer DTOs** — plain data classes without annotations (internal use)
3. **Naming**: `<Action>RequestDto` at controller, `<Action>Request` at service (dual pattern)
4. **Placement**: Mixed — some inline in controller file, some in service file
5. **Conversion**: Controller DTO → Service DTO mapping done in controller (manual mapping)
